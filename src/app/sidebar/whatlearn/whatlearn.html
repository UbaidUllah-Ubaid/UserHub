01 WHAT I LEARNED

Controlling Data Visibility with One Button

While building UserHub, I faced a problem where I needed to show and hide a post's comments using the same button. I solved this by maintaining a boolean state that tracks whether the comments are visible or hidden. This taught me how the UI can respond to changes in application state.

Real-World Use

02 WHAT I LEARNED

Master-Detail Pattern & Data Flow

While building UserHub, I learned how to fetch only the data related to a selected user. For example, when a user is selected, I need that user's ID to fetch only their posts instead of loading every post.

01
Separation of Concerns

The Service handles data fetching, while the Component focuses on displaying and interacting with the data.

02
Filtering Through Parameters

The selected user's ID is passed to the Service so it can request only the posts belonging to that user.

03
Parent-to-Child Data Flow

The parent passes the selected user's ID to the child component using Property Binding and @Input().

04
Component & Service Integration

The child component receives the ID and uses it to call the Service and retrieve the required posts.

Real-World Use

This pattern is useful whenever one piece of data depends on another, such as customers and their orders, products and reviews, employees and their projects, or accounts and their transactions.
